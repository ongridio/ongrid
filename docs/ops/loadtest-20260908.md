# APM 本地容量与 SDK 开销：2026-09-08

## 目标和环境

检查应用指标查询在 100/500/1000 服务时的完整性和耗时，并比较官方自动埋点对最小 HTTP 示例的影响。使用合成数据和测试应用，不导入业务数据，不向生产后端写测试指标。

- Apple M3 Pro，12 逻辑 CPU，18 GiB 内存；OrbStack Docker 可用 12 CPU、约 8.78 GiB 内存。
- macOS ARM64 原生应用：OpenJDK 25.0.1、Node 22.22.3、Python 3.14.3。
- 独立容器：Prometheus 2.54.0、Tempo 2.10.0、OTel Collector Contrib 0.157.0；复用安装配置与生产 Collector 渲染代码。
- 本地既有服务保持运行；测量期间未同时执行镜像构建。此机器、负载和运行时组合不是生产拓扑。

## 查询规模

每服务一个实例，HTTP/RPC 各两种状态，六个桶加计数器，共 28 条时序、每条 11 个一分钟间隔的数据点。错误率固定 25%。通过现有 remote_write 客户端注入，调用生产 APM Service 和 Prometheus 适配器，检查总数、分页及错误率；每档并发 1/4/8，每个工作线程查询三次，Go 测试启用 `-race`。

该结果包含查询用例和真实 Prometheus 往返，未包含 Manager HTTP 登录中间件、浏览器渲染或跨机网络。统计量来自短批次，并发 1 只有三次查询，P95 接近最大值；不得当作长期 SLO。数据规模按活跃时序变化，不能仅以“服务数”外推。

## SDK HTTP 开销

三语言分别运行无埋点、原生 Metrics 加关闭 Trace 采样、原生 Metrics 加全量 Trace 三种模式。每种三轮独立进程，200 次预热后四个工作线程连续十秒、目标总计 200 请求/秒；OTLP 每秒导出到真实 Collector，覆盖多个导出周期。记录成功请求量、实际吞吐、P50/P95 与结束时进程 RSS，比较三轮中位数。固定负载用于比较延迟和内存，吞吐不代表饱和容量。

这不是业务 CPU 百分比：没有采集 CPU 使用率或长期内存稳态。HTTP 客户端在服务端允许时复用连接，Python 使用 Flask 开发服务器，Java 预热有限；日志始终写 stdout。初版不限速短连接客户端在连续数万请求后超时，其结果废弃。数据用于发现显著差异，不代表生产框架、长时间运行、RPC 或真实业务开销。

## 拐点和后续

本次有限规模未搜索系统极限或给定业务 SLO，因此不宣称已找到容量拐点。查询成本随时序规模和并发上升；生产接入前应按真实协议/接口/实例基数、查询范围和保留期重复测试，并持续观测 Prometheus CPU/内存、Collector 队列/丢弃以及应用 CPU/尾延迟。容量至少预留 30%，实际规格需目标环境数据决定。

复现：`make test-apm-acceptance`。原始数据在 `output/apm-acceptance/overhead.json`，容量每档的 JSON 由 `TestAPMCapacityIntegration` 输出。

## SDK 实测结果

以下为三轮中位数，延迟单位 ms、RSS 单位 MiB。全部请求成功。

| 语言 | 模式 | 实际 RPS | P50 | P95 | RSS |
|---|---|---:|---:|---:|---:|
| java | 无埋点 | 175.5 | 0.55 | 1.83 | 73.6 |
| java | Metrics / Trace 采样关闭 | 175.9 | 0.66 | 2.39 | 129.2 |
| java | Metrics / Trace 全采样 | 175.7 | 0.70 | 3.61 | 115.5 |
| node | 无埋点 | 177.0 | 0.51 | 1.95 | 81.0 |
| node | Metrics / Trace 采样关闭 | 176.9 | 0.67 | 1.91 | 104.5 |
| node | Metrics / Trace 全采样 | 177.0 | 0.68 | 1.95 | 104.4 |
| python | 无埋点 | 176.9 | 0.85 | 1.75 | 31.5 |
| python | Metrics / Trace 采样关闭 | 177.1 | 1.00 | 2.62 | 48.0 |
| python | Metrics / Trace 全采样 | 176.5 | 1.10 | 3.48 | 46.8 |

目标为 200 RPS，实测约 174–178 RPS；客户端线程调度和 sleep 精度影响实际速率。应以表中实际值理解负载，不能将其差异直接归因为 SDK 吞吐损失。
