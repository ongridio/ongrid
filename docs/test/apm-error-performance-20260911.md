# 错误聚合性能优化验收

日期：2026-09-11。基线提交：`dd8fdac3`。范围：本地 Manager/Web 与 Tempo Go 演示服务。

## 修改

- 保留每协议最近 50 条错误 Trace、完整详情匹配、堆栈归组、失败/截断提示；不缩小时间范围、不减少样本，也不改成只看根 Span。
- 增加显式分页快照。快照绑定调用者与完整查询范围，2 分钟过期，最多 8 份、每份 2 MiB；超大结果只跳过缓存，不截断分组。刷新不读缓存，避免掩盖新到 Span 或之前失败的详情。
- HTTP/RPC 独立分页；已看过的页直接复用。读取详情并发 4→8，所有错误查询共享 16 个读取槽位；Tempo 默认客户端同主机空闲连接池由默认 2 调为 16，减少反复建连。

## 实测

固定同一服务、环境、命名空间和一小时时间窗，结束时间距测量时刻两分钟。原实现与新实现交替各测 3 次，保留原实现的默认连接池作为基线。比较整个 ErrorGroups 返回值，仅忽略新增的快照 ID。

| 项目 | 原实现 | 优化后 |
|---|---:|---:|
| 完整查询耗时中位数 | 1114.17 ms | 812.38 ms |
| 100 次快照分页平均业务处理时间 | 每页重新搜索及读取详情 | 0.017 ms |
| 快照分页新增 Tempo 详情读取 | 每页最多 50 次 | 0 次 |

完整查询约快 27%。50 条样本、1 个错误组、0 条失败详情，指纹、计数、时间、版本/实例、代表链路与堆栈等证据逐字段一致。分页时间是进程内业务处理时间，不包含网络及浏览器；此结果不代表生产延迟或全量错误覆盖。

只增加并发的早期测试未获得稳定收益，因此同时修正连接复用后才保留并发调整。没有使用按时间裁剪 Trace 详情的捷径：[Tempo API 文档](https://grafana.com/docs/tempo/latest/api_docs/) 明确说明该方式可能返回部分 Trace，存在遗漏 Span 的风险。

部署后的真实 HTTPS API 验证：首次查询 3945 ms，快照查询 18 ms，重新刷新 5926 ms。快照证据完全一致，刷新返回新的快照 ID。容器内同窗口直接读取 Tempo 的 4/8 并发测量分别为 1.31/0.786 秒；不能把组件基准当作完整页面延迟，首次读取仍有秒级波动，本轮未将其宣称为已消除。

另验证了 TraceQL `select` 一次返回堆栈的方案，单次搜索约 0.18 秒，但未采用：[Tempo 2.10.0 的 AllAttributes 实现](https://github.com/grafana/tempo/blob/v2.10.0/tempodb/encoding/vparquet4/block_traceql.go) 会将多条事件的同名属性覆盖到一个 map，搜索结果无法证明事件证据完整。为避免遗漏，不用这种摘要代替完整 Trace。

## 回归验证

- Go `-race`：APM 业务、APM HTTP、Trace 查询客户端；覆盖分页不读 Tempo、完整分组保留、失败详情恢复后刷新可见、调用者/版本/时间/协议/集群隔离、快照过期及容量限制、四个并行请求全部读取 200 条样本且全局并发不超过 16。
- 连接复用测试：两批各 8 个同时读取的请求只建立 8 条连接。
- 前端：APM、ErrorGroups、ErrorTraces 定向测试，验证翻页不重查另一协议、返回已看页不发请求、刷新重置分页且不携带旧快照。
- 快照过期后重试从第一页重新读取，不触发另一协议重查；前端共 31 项定向测试通过。ESLint、Protobuf 生成、Manager/Web 生产镜像构建通过。实际页面保留 50 条样本、不完整提示和堆栈入口，截图已核对。
- 本地监听测试首次受沙箱限制，在允许本机临时监听后重跑；与产品代码失败区分记录。
