# 模型上下文预算与对话展示验收（2026-11-17）

## 范围与结果

- 每次 v2/v3 模型请求按实际选择的 provider/model 确定上下文窗口。优先使用合法的模型目录元数据，其次使用内置精确型号/日期快照规格；未知型号和私有别名使用全局配置。输出仍受全局输出上限及已知模型输出上限约束。
- Base64 图片数据不再按文本字节计入上下文。图片使用尺寸及模型规则估算，原始图片和已保存消息不变。上传校验与预算估算复用同一个 PNG/JPEG/WebP 尺寸读取函数。
- 大型 `capture_pcap` 结果被保存和缩略后，保留有界的抓包操作信封，供现有操作卡片轮询、查看及停止。外部工具不能通过同名结构注入此信封。
- 主对话与侧边助理共用上下文圆环，通过 `context_usage` SSE 展示最近准备发送的输入估算。弹层说明估算范围、输出预留、窗口来源；无估算时仅显示容量，切换模型不显示不匹配的用量。刷新后用量需等待下一次请求，不把累计计费用量当作上下文。

## 实际模型与界面

测试环境：本机 Linux arm64 Docker Manager/Web，镜像标记 `v0.20.0-context-budget.20261117`。保留环境变量、数据挂载和网络；Manager 文件 SHA-256 一致，`healthz` / `readyz` 均为 200。前一版镜像和私有 Compose 配置保留用于回滚；生产未更新。

使用正常聊天 UI 向已配置的 `gpt-6.1-terra`（Low）发送一张 196,947 字节、256×256 的红蓝合成 PNG。模型正确回复“左半边是红色，右半边是蓝色”，未触发上下文拒绝。该次估算为 110,203 / 1,050,000 tokens，含系统提示、工具定义与协议预留，并非图片本身或计费 token 数。短追问正常完成，估算更新为 110,879。

切换到未知模型 `mimo-v2.6-flash` 时，UI 显示全局兜底容量 131,072，隐藏原模型用量；没有向该型号发送测试请求。恢复原模型后继续展示匹配的估算。

通过真实浏览器检查 390、768、1280、1920px × 中文/英文 × 浅色/深色共 16 种组合，保存整页截图、视口/容器边界与圆环中心点可点击断言。首次截图发现右侧圆环可被既有悬浮助理覆盖，因此将圆环移至模型选择器旁，并对最终布局重新验收。侧边助理另外通过四种宽度下的弹层和可点击性检查。测试后恢复语言和主题设置。键盘打开、未知容量和模型切换状态另有组件回归测试。

本地证据目录为 `output/context-budget-20261117/`，不提交其中的运行产物和私有部署配置。主要记录：`full-go.log`、`affected-race.log`、`final-race.log`、`cmd-race.log`、`web-tests.log`、`visual-check.mjs`、`visual-check.json`、16 张截图和 `deployment-check.json`。
