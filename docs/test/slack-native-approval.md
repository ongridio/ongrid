# Slack 原生审批实际验收

使用专用测试机器人私聊完成验收。本记录不包含环境地址、工作区或用户身份、机器人凭证、会话及审批记录 ID。

## 已通过

- 应用安装、Bot API 鉴权、Socket Mode 连接及真实私聊事件接收。
- 限定测试账号白名单；通过 `/ongrid-bind` 领取口令，后台核对实际消息身份后确认绑定。
- 卡片展示操作参数，批准和拒绝均在 Slack 内完成，无需跳转 Web。
- 批准前临时文件不存在；批准后命令执行成功，文件内容符合预期。后台记录显示决策时间早于执行时间。
- 原卡片更新为执行成功，展示执行结果并移除按钮。
- 拒绝后后台状态为 rejected，目标文件未创建。
- 测试文件、临时凭证及临时截图已清理；健康检查通过。

## 发现的问题

批准后的 Agent 总结错误地将工具返回执行成功解释为“审批门禁未拦截、直接放行”。实际卡片、文件检查和后台时间记录证明先批准后执行。

根因已定位：审批等待结束时只返回执行器原始输出，模型没有收到审批决策事实；不能据此认定授权被绕过。

代码已统一补充 `_ongrid_approval` 元数据，包含审批记录引用、决策、终态以及“等待人工批准后才尝试执行”的说明。仅在持久化记录有决策人和决策时间时标记 approved；未确认的失败保持 unknown。保留原始工具字段和错误，不修改持久化执行结果，也不调整审批权限或状态机。

`go test -race` 已验证审批成功、失败、拒绝、取消、缺失决策证据、非对象结果及大整数保留；v2/v3 实际 Runtime 回归确认模型同时收到工具结果和审批事实，通用工具 Broker 回归确认批准前不执行、批准后仅执行一次。

此次代码修复尚未部署；真实 Slack 模型总结仍待部署后复验，不能把确定性的模型输入回归等同于线上自然语言总结已经通过。
