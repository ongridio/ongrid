# Telegram 原生审批验收

通过真实机器人私聊和后台确认完成身份绑定，以下场景已通过实际验收。
记录仅保留通用结论，不包含环境地址、机器人名称、用户身份或业务记录 ID。

| 场景 | 结果 |
| --- | --- |
| 身份绑定 | 私聊领取绑定挑战，后台确认成功 |
| 批准 | 卡片展示完整参数；点击批准后执行成功，验证临时文件内容一致 |
| 结果回写 | 原卡片更新执行结果，移除操作按钮，机器人返回总结 |
| 拒绝 | 审批变为 rejected，验证目标文件未创建 |
| 清理 | 测试文件、临时网络转发和凭证临时文件已清理 |

本次未进行 Slack / 钉钉真实账号端到端验收。

## 部署要求

服务端必须能够访问 Telegram API；如需代理，通过部署配置注入，不能依赖开发者电脑的临时转发。
凭证通过产品配置保存，不写入代码、示例或验收文档。

## 回滚

使用部署时在环境内保留的 Compose 配置和镜像引用恢复原版本，保留身份绑定及审批数据。
回滚时不得恢复已撤销的临时代理配置。备份位置和具体操作记录仅在环境内保存。
