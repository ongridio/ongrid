# 服务与设备自动拓扑验收

## 行为

- 侧栏、路由搜索和页面标题将“应用性能”统一为“服务”，现有 `/apm` 地址及指标、链路、日志、实例功能保留。
- Manager 启动后及每 30 秒独立读取当前遥测，自动维护 `service --deployed_on--> device`；打开页面、筛选和分页不会触发或限制同步。
- 服务身份是环境、服务命名空间、服务名三元组。版本和实例不拆分服务；多个实例在同一设备上只生成一条关系，多设备部署保留多条关系。
- 通过设备表的 `node_id` 解析上报的 `device_id`，不按设备名称匹配，也不把设备 ID 当作拓扑 ID。缺少设备身份的服务可以建节点，但不会猜测设备关联。
- 原生资源指标按最近 5 分钟的样本时间判断有效性，零请求的持续指标上报仍有效。Trace-only 服务要求最近 5 分钟有计数变化或新序列，避免 Tempo 重复刷新旧计数导致旧关系永久保留；遥测后端的采集、缓存及序列失效延迟仍适用。
- 完整成功的快照先补全当前关联，再清理已不在快照中的自动关联。查询失败、解析失败、设备解析失败或超过 5000 条部署时保留原关系。服务节点保留以维持历史身份。
- 上报节点和关联使用 `source=apm`。通用拓扑 API 禁止手工创建该来源、修改或删除自动节点/关联，以及手工添加自动服务与设备之间的关系。内部同步直接调用已有仓储，不开放可绕过的前端参数。
- 两种拓扑视图均显示“托管”并隐藏删除入口，添加关系时过滤受保护的设备与服务配对；服务节点可以跳转至完整身份范围的服务详情。
- 原有手工服务和其他手工关系保留。服务创建沿用当前单 Manager 同步模型；多 Manager 同时写入前需增加数据库服务身份唯一约束。

## 验证

- Go `-race`：APM 与拓扑包通过，覆盖多设备、重复快照、同名跨环境、未知设备、迁移、停报清理、失败保留、身份保留及通用变更入口保护。
- Prometheus 2.54 `promtool`：实际执行查询，覆盖同标签 count/sum 多指标、原生空闲服务、跨环境服务、失效序列和持续刷新但没有新 Span 的计数。
- 前端 21 项测试通过，包含服务标题、拓扑两个视图的双向只读展示和服务详情身份跳转；TypeScript、ESLint、前后端构建通过。
- 本地真实上报已生成 `apm-demo-go` 服务（development / apm-demo）及其到 `ubuntu` 的部署关系。设备页确认设备主键为 650，拓扑服务节点为 105；两个 Go 实例共用一条设备关联。
- 已通过实际页面核对自动关系只读、侧栏名称和服务详情跳转。迁移与停报撤销由自动化测试验证，未停止或迁移现有演示容器来制造现场故障。
