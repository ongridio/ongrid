# RFC-009：Agent Runtime v2/v3 隔离与显式切换

- 状态：提议；用户已确认仅管理员设置入口、release 默认最新稳定 Runtime，尚未实现
- 日期：2026-10-16
- 关联：PR #503、RFC-008、ADR-035；PRD-009
- 基线：正式发布标签 v0.18.2（`3b41874cae792329fd61cfe0450e57335efa3f1d`）的 Graph；不把已退役的 legacy for-loop 当作 v2

## 背景与目标

用户需要在新版 Agent 效果不佳时切回熟悉的行为，同时隔离实现。Agent Runtime 版本独立于 Ongrid 产品版本和模型版本：v2 是已发布 Graph 的行为基线，v3 是当前统一目录、权限和工具生命周期改进。当前代码仍只有一个 Graph 实现，本文不是已交付功能声明。

## 版本与隔离边界

拟定结构：

```
internal/manager/biz/aiops/
  chatprotocol/          # 稳定边界，不引用版本实现
  runtime/contract/      # 请求/回复、worker/目录管理契约
  runtime/v2/            # 发布基线的循环、上下文策略、prompt、装配策略
  runtime/v3/            # 本次改进，后续行为变更在此进行
internal/manager/service/aiops/
  runtime_router.go     # 依据会话记录选版本，禁止自动降级
```

v2/v3 不互相 import；入口只依赖契约。代码位置仍需结合实际依赖图细化，不能仅给两个名字包一层相同实现。目录装配、工具暴露、上下文压缩、worker 策略及内置 prompt 均是行为版本的一部分。业务工具的底层 IO、存储、鉴权、审计和审批领域服务复用；版本对应的工具集合/装饰策略分别装配。

共享工具或 Eino 依赖升级可能改变两个版本，必须同时跑契约和行为回归；必要时保留版本适配器，不能声称共享依赖下逐字节复现旧发布。模型与外部 Skill/MCP 可变，版本回退保证的是运行时策略；记录实际模型、prompt 版本、工具目录摘要，方便解释差异。安全修复同时覆盖 v2/v3，不提供回退绕过安全约束的能力。

## 路由与切换（建议默认）

- 仅在设置 → AI / Agent 设置提供管理员版本切换；每次 release 的默认值为该发布包含的最新稳定 Runtime。建议保留管理员显式指定的版本，不在升级时覆盖回退选择。
- 聊天页不提供版本选择器；新会话采用管理员设置或 release 默认值。建议已有会话保持绑定版本，默认不复制工具历史或待审批动作。
- `chat_sessions.runtime_version` 持久化选择。明确来自既有发布、且无版本标记的会话归 v2；PR 试验环境中已生成的 v3 会话需显式标记，不能统一回填为 v2。
- coordinator、同步/后台 worker、报告、告警和工作流 Agent 节点均绑定版本。子任务继承父版本；无父会话的任务在创建时解析一次默认版本。
- IM 既有会话保持版本，新会话使用默认；将来如加用户偏好也只影响新会话。
- v3 不可用时明确失败，不静默路由到 v2。停用版本仅阻止新建，已有任务/审批不跨版本迁移。

## 审批与共享状态

沿用 Graph 审批链和 `approvals`。新动作记录来源 runtime 版本，审批始终回到原版本执行器/内存执行能力；修改默认版本不得改变待审批行为。缺失版本能力、已取消、超时或内存能力丢失时明确失败，要求重新发起。

不引入审批自动恢复或后台重放。旧 legacy K8s 执行入口删除，历史 payload 的只读解析保留。两个 Runtime 各自管理 worker、工具快照与 MCP 更新；共享注册器避免重复指标注册，低基数 runtime_version 标签用于区分。不能让两个实例共享可变工具目录或通过全局变量切换当前版本。

## API、数据与发布

先更新 proto，再增加会话创建/查询 DTO 的可选 runtime_version 和支持版本列表；非法或不可用版本明确拒绝。现有客户端不传时由服务端选默认。前端复用系统设置组件，仅管理员可以切换；聊天页不新增版本选择器。不将 Edge Agent 版本与 Runtime 版本混用。

按项目当前 schema 管理方式做加法字段与回填，滚动升级兼容；读取端先兼容空值再写入明确版本。回滚默认版本只影响新会话；回滚整个旧镜像无法保证读取 v3 语义，必须单独验收，不把版本切换当镜像回滚替代。

## 实施与验收

开始：2026-10-16；完成时间由验证结果决定，里程碑各按 1–3 天工作量拆分。

1. 固定 v2 发布提交、记录行为样例，完成契约与依赖清单；先完成当前审批退役修复。
2. 抽出版本无关协议，隔离 v2/v3 的编排及 prompt；所有入口通过统一路由。
3. 加会话版本字段、默认设置、API 与选择界面；同步 worker、IM、报告、工作流入口。
4. 双版本回归及真实模型对照验收，v3 灰度；保持 PR 草稿，不合并/部署。

必须验证：v2 发布行为样例；v3 safe Skill/web toggle 修复；跨版本不共享工具状态；worker 继承；默认版本变更不改变旧会话；待审批版本不漂移；非法版本拒绝；两版本并存时无指标注册 panic/数据竞争；历史会话升级与旧镜像回滚边界。分别记录延迟、工具成功率和任务完成结果，不能只比较最终文本。

## 备选与风险

- 只做模型或 prompt 开关：不能隔离循环和工具行为，不采用。
- 通过镜像回滚选择版本：适合整个部署回退，不能满足用户级试用。
- 完整复制所有工具和业务服务：隔离强，但安全修复易分叉、维护成本高；优先隔离策略并共享业务执行能力。
- 长期同时维护两个版本增加测试成本；v2 仅做必要兼容和安全修复，后续退役需明确公告与迁移策略。

## v1 历史核对（2026-10-16）

v1 是对旧 `internal/manager/biz/aiops/agent` 手写循环的追溯命名，历史代码称为 legacy，并没有原生的 v1 版本字段。

| 参照 | Git 基线 | 说明 |
| --- | --- | --- |
| 最早公开实现 | `efbda840fa2f3e927a4681a29229b716796b6d32`，2026-05-24 | 首次公开提交已同时包含 legacy 和 Graph，不能据此推断 Graph 的真实初创日期 |
| 中期发布参照 | `v0.12.0 / ba6f4628` | Service 默认 legacy，但两个 Compose 配置均默认 graph，部署默认和代码默认不同 |
| 代码默认切换 | `b94c8ae1`，2026-08-14，首次进入 `v0.13.0` 标签 | ParseKernel 的缺省值改为 Graph，仍可显式 legacy |
| 后期 v1 参照 | `v0.18.2 / 3b41874c` 的 `biz/aiops/agent/` | 发布时仍包含 legacy 实现，累积了历史回放、附件和审批等兼容修改 |

v1 的核心路径是：加载历史 → 调用 llm.Chat → 串行 Registry.Invoke → 持久化工具结果 → 下一轮；默认最多 30 轮、工具超时 15 秒（有工具专属覆盖）。循环直接承担模型调用、回放、SSE 事件与持久化，未采用 Graph/Eino 编排。

后期 v1 不等于最初 v1：评估简单循环架构看最早参照；评估兼容成本看 v0.18.2 中的后期参照。v1 依赖旧 Registry 和专用审批适配，恢复运行需要单独迁移验证，不能仅复制 agent.go。目前仅保留历史参照，不恢复生产入口，也未承诺提供 v1 切换。
