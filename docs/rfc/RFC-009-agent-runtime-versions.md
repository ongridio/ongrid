# RFC-009：Agent Runtime v1/v2/v3 隔离与显式切换

- 状态：v2/v3 切换已部署测试环境；v1 不再支持，保留源码归档；未推送、未合并
- 日期：2026-10-16
- 关联：PR #503、RFC-008、ADR-035；PRD-009
- 基线：正式发布标签 v0.18.2（`3b41874cae792329fd61cfe0450e57335efa3f1d`）的 Graph；不把已退役的 legacy for-loop 当作 v2

## 背景与目标

用户需要在新版 Agent 效果不佳时切回熟悉的行为，同时隔离实现。Agent Runtime 版本独立于 Ongrid 产品版本和模型版本：v2 是已发布 Graph 的行为基线，v3 是当前统一目录、权限和工具生命周期改进。三个版本源码已隔离；当前本地实现同时装配 v2/v3，release 默认 v3。下文按日期保留阶段记录，最新切换行为见末节。

## 版本与隔离边界

拟定结构：

```
internal/manager/biz/aiops/
  chatprotocol/          # 稳定边界，不引用版本实现
  runtime/contract/      # 请求/回复、worker/目录管理契约
  runtime/v1/            # 首个正式 release v0.7.158 的 Eino Graph
  runtime/v2/            # 发布基线的循环、上下文策略、prompt、装配策略
  runtime/v3/            # 本次改进，后续行为变更在此进行
internal/manager/service/aiops/
  runtime_router.go     # 依据会话记录选版本，禁止自动降级
```

v1/v2/v3 不互相 import；入口只依赖契约。代码位置仍需结合实际依赖图细化，不能仅给两个名字包一层相同实现。目录装配、工具暴露、上下文压缩、worker 策略及内置 prompt 均是行为版本的一部分。业务工具的底层 IO、存储、鉴权、审计和审批领域服务复用；版本对应的工具集合/装饰策略分别装配。

共享工具或 Eino 依赖升级可能改变两个版本，必须同时跑契约和行为回归；必要时保留版本适配器，不能声称共享依赖下逐字节复现旧发布。模型与外部 Skill/MCP 可变，版本回退保证的是运行时策略；记录实际模型、prompt 版本、工具目录摘要，方便解释差异。安全修复同时覆盖 v2/v3，不提供回退绕过安全约束的能力。

## 路由与切换（建议默认）

- 仅在设置 → AI / Agent 设置提供管理员版本切换；每次 release 的默认值为该发布包含的最新稳定 Runtime。建议保留管理员显式指定的版本，不在升级时覆盖回退选择。
- 聊天页不提供版本选择器；新会话采用管理员设置或 release 默认值。建议已有会话保持绑定版本，默认不复制工具历史或待审批动作。
- `chat_sessions.runtime_version` 持久化选择。历史空值不推断、不批量回填；保持此前实际执行默认 v3，避免切换设置时迁移既有会话。确需恢复旧发布会话归属时，必须另行验证来源后迁移。
- coordinator、同步/后台 worker、报告、告警和工作流 Agent 节点均绑定版本。子任务继承父版本；无父会话的任务在创建时解析一次默认版本。
- IM 既有会话保持版本，新会话使用默认；将来如加用户偏好也只影响新会话。
- v3 不可用时明确失败，不静默路由到 v2。停用版本仅阻止新建，已有任务/审批不跨版本迁移。

## 审批与共享状态

沿用 Graph 审批链和 `approvals`。新动作记录来源 runtime 版本，审批始终回到原版本执行器/内存执行能力；修改默认版本不得改变待审批行为。缺失版本能力、已取消、超时或内存能力丢失时明确失败，要求重新发起。

不引入审批自动恢复或后台重放。旧 legacy K8s 执行入口删除，历史 payload 的只读解析保留。两个 Runtime 各自管理 worker、工具快照与 MCP 更新；共享注册器避免重复指标注册，低基数 runtime_version 标签用于区分。不能让两个实例共享可变工具目录或通过全局变量切换当前版本。

## API、数据与发布

先更新 proto，再增加会话创建/查询 DTO 的可选 runtime_version 和支持版本列表；非法或不可用版本明确拒绝。现有客户端不传时由服务端选默认。前端复用系统设置组件，仅管理员可以切换；聊天页不新增版本选择器。不将 Edge Agent 版本与 Runtime 版本混用。

按项目当前 schema 管理方式做加法字段与回填，滚动升级兼容；读取端先兼容空值再写入明确版本。回滚默认版本只影响新会话；回滚整个旧镜像无法保证读取 v3 语义，必须单独验收，不把版本切换当镜像回滚替代。

## 实施与验收

开始：2026-10-16；完成时间由验证结果决定，里程碑各按 1–3 天工作量拆分。

1. 固定 v2 发布提交、记录行为样例，完成契约与依赖清单；先完成当前审批退役修复。
2. 抽出版本无关协议，隔离 v2/v3 的编排及 prompt；所有入口通过统一路由。
3. 加会话版本字段、默认设置、API 与选择界面；同步 worker、IM、报告、工作流入口。
4. 双版本回归及真实模型对照验收，v3 灰度；保持 PR 草稿，不合并/部署。

必须验证：v2 发布行为样例；v3 safe Skill/web toggle 修复；跨版本不共享工具状态；worker 继承；默认版本变更不改变旧会话；待审批版本不漂移；非法版本拒绝；两版本并存时无指标注册 panic/数据竞争；历史会话升级与旧镜像回滚边界。分别记录延迟、工具成功率和任务完成结果，不能只比较最终文本。

## 备选与风险

- 只做模型或 prompt 开关：不能隔离循环和工具行为，不采用。
- 通过镜像回滚选择版本：适合整个部署回退，不能满足用户级试用。
- 完整复制所有工具和业务服务：隔离强，但安全修复易分叉、维护成本高；优先隔离策略并共享业务执行能力。
- 长期同时维护两个版本增加测试成本；v2 仅做必要兼容和安全修复，后续退役需明确公告与迁移策略。

## 统一契约与路由：能力保留检查（2026-10-16）

已抽取 `runtime/contract` 的完整请求、回复、流事件、Worker 快照与上下文载体。v3 使用类型别名保持调用兼容，Worker 锁和 cancel 仍留在 v3 私有状态，v1/v2 冻结源码不变。Service 侧 `RuntimeRouter` 接管聊天与外部 Worker 调用；当前只注册 v3，默认版本和注册表不可变，未开放用户切换，也没有会话版本迁移。未知或未装配版本明确拒绝，不自动降级。

Worker 查询、继续、停止按实例实际归属分派，覆盖内部 reviewer 创建的 Worker；重名导致归属不明确时拒绝控制。后台 Worker 保留版本和权限快照，不继承请求取消和 SSE callback 状态。此处的版本上下文是进程内执行归属，不替代未来的会话/审批持久化版本。

## 新会话版本持久化（2026-10-17）

已增加可空 `chat_sessions.runtime_version` 字段，通过项目现有 AutoMigrate 做加法升级。新会话创建时读取路由器的默认版本并保存；当前仅装配 v3。v3 Worker（包括内部 reviewer、独立系统任务）写入 v3，后台 context 继续保留版本。HTTP 会话响应和 proto 增加只读可选 `runtime_version`，前端 API 类型同步，不增加聊天页选择器。

生产路由器读取会话/父会话的持久化版本，显式 context 与记录冲突时拒绝执行；未装配或未知版本不自动降级。v3 入口也校验版本，防止内部直接调用绕过路由。缺失的父会话在路由入口明确失败，避免把有归属的请求变成无父任务；无父会话的系统任务继续使用默认版本。

历史空值暂不回填、不推断。当前仍只有 v3，空值沿用现有执行方式；这不是完成历史迁移，也不能据此开放默认版本切换。正式发布历史会话与试验环境历史会话的来源分类、旧版本适配及独立可变目录仍是开放切换前的必需项；审批来源版本已在后续阶段接入，见下节。

验证：SQLite 模拟缺列升级并连续迁移两次，历史空值保持不变；新记录重读、改标题/模型后版本仍保留。路由回归覆盖固定版本优先、context 冲突、未知/未装配版本、父任务继承和缺失会话。真实 Manager + 临时 MySQL 的聊天、RCA 和工作流 E2E 通过（35.118s；模型为测试替身）。

回滚：恢复前一代码/镜像，保留新增可空列即可，不需要删除列或还原聊天数据。旧代码不会执行版本约束；在多版本能力开放后不能把这种镜像回滚视为等价版本切换。本阶段未部署或推送。

## 审批来源版本与执行归属（2026-10-17）

`approvals.runtime_version` 记录提案产生时的执行版本。cloud_bash、host_bash、MCP、安装 Skill 和通用工具审批均从原始执行 context 写入；审批 HTTP 响应及前端 API 类型回显该字段，批准请求不能改写归属。补充审批实体 proto 契约，不改变现有接口路径。

审批用例按 `(kind, runtime_version)` 精确选择执行器，不读取当前默认版本，也不回退到其他版本或无版本执行器。Service 装配恢复来源版本到执行 context。执行器注册表使用读写锁，执行期间不持锁。通用工具的内存单次能力另带版本校验，拒绝跨版本执行和重复使用；重启后能力丢失仍明确失败，不自动重建、重放或恢复。

当前仅注册 v3 的版本化执行器。现有无版本 Graph 审批/非 Runtime 用例继续通过独立空版本键执行，旧数据不回填；已退役的 legacy K8s 执行器没有恢复。v1/v2 尚未装配，标记这些版本的提案会在缺少执行器时明确 failed，不能借通用执行器绕过。

验证：持久化后重建审批用例，原版本执行器仍被选中；原版本缺失时其他执行器零调用；并发注册/批准、重复批准及单次能力的版本匹配/拒绝通过 race 测试。MCP 批准请求携带不同版本 context 时仍恢复提案来源。SQLite 缺列升级与重复迁移保留旧记录状态及空版本。真实 Manager + 临时 MySQL 聊天和抓包审批拒绝 E2E 通过（25.958s，模型为替身），审批 API 回显 v3。

回滚限制：新增列可保留，不做破坏性迁移；但旧代码不识别审批版本约束。多版本启用后，回滚到无版本路由的旧镜像前必须先停止接收新提案并处理待审批记录，不能声称仅换镜像就保留版本隔离。此阶段未部署、推送或合并。


### 管理员运行时选择入口（2026-10-17，本地实现）

「设置 → 助理」第二张配置卡增加运行时下拉框。`agent.runtime_version` 通过既有系统设置 API 保存：`release` 跟随发行版默认，`v3` 固定当前已装配引擎。当前两者均执行 v3；v1/v2 仅显示为禁用选项，后端单项及批量写入也拒绝这些值。本阶段不代表完成多版本切换。

新会话和无父会话的系统任务读取持久化选择；已绑定会话与子任务沿用其归属，未分类历史会话固定使用当前装配默认（v3），不查询新会话设置。设置读取失败或数据库存在不支持的值时，新会话失败而不是静默切换引擎。历史来源分类与 v1/v2 适配、独立目录和审批执行器仍须完成，之后才能开放对应选项。

回滚：恢复前一代码即可，新增设置行可以保留（旧版不读取）；也可以删除 `agent/runtime_version` 恢复发行版默认。没有本阶段新增 schema。尚未推送或部署。

### v3 动态能力收口（2026-10-17，未推送、未合并）

保持 Eino Graph、Worker、Approval/Operation 既有状态流转；不将 `TurnPlan` 的阶段枚举误当成完整持久化执行状态机，也不在本次重写 runtime。

- Skill：每轮提供名称/说明目录和 `load_skill`；新增显式 `on_demand`，保留默认/`always` 和 `keyword` 自动加载。Worker 使用自己的任务解析 Skill，并按实际加载的 Skill 重新解析凭据绑定，不继承协调者的整组凭据。
- `load_skill` 输出版本、资源指纹、资源目录和正文，进入现有工具消息持久化链路；自动加载的版本写入 runtime span。资源采用回合副本，包含所属插件的相对脚本/资源；审批执行另外取得引用，聊天取消不能删除已开始执行的命令正在使用的资源。最后一个引用释放后清理临时副本。
- 卸载会撤销后续资源获取；正常 registry 热更新保留已有任务副本。当前 marketplace 没有原地升级 API，重复安装返回冲突；卸载再装属于撤销和新安装，不视为平滑升级。重启后的旧内存副本不可恢复，相关未完成审批必须重新发起，不能悄悄换用当前版本。
- MCP：手动连接测试、启动发现和后台发现走同一发布路径；并发探测按开始顺序确定最新结果，修改/禁用/删除使旧探测失效。临时网络失败保留最后验证的工具；后台刷新不替换内容未变的执行句柄。
- MCP 新审批保存配置/凭据/工具目录指纹，执行前核对，禁止旧批准跳转到新端点或新凭据。禁用服务在执行入口直接拒绝。v3 中不带配置指纹的旧待审批操作要求重新发起；非 runtime 的历史路由仍检查启用状态。
- MCP 按 [`tools/list` 分页与变更通知](https://modelcontextprotocol.io/specification/2025-03-26/server/tools)发现全部工具；支持 [`Streamable HTTP GET SSE`](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports) 的服务可主动通知刷新，每分钟发现作为无通知服务及断线后的兜底。每个服务一条顺序刷新链路，关闭时取消并等待退出。

回滚：测试部署保留旧 Manager/前端镜像、Edge 二进制、Compose 配置和数据库备份。新增 Skill 加载模式只用于明确配置的 Skill；旧 runtime 不识别 `on_demand`，回滚前应还原这类新配置。临时资源副本不是持久化发行版目录，不承诺跨进程续跑。测试部署与现场验证结果单独记录，不以本地测试通过代替现场验收。

### v2 可用回退与 v1 退役（2026-10-17，本地实现）

「设置 → 助理」第二张卡片现在支持 `release`、`v3`、`v2`；v1 文案为「不再支持」，后端继续拒绝。v1 源码和来源清单保留。release 仍默认 v3，用户主动选择 v2 后只有新会话及无父会话的新任务采用 v2。

v2 的 Graph/Worker 真实独立执行，Service 仅适配协议与 Worker 快照。两套 Skill/Agent registry、工具袋和 reviewer 分别装配；共享 LLM 配置、业务服务、底层工具、审批存储及可复用指标。MCP 只有一个发现监督器，结果分别发布到两套目录；安装/卸载同时重新加载两套 registry。每个版本的工具撤销独立生效，旧 schema 引用不能调用新端点。

v2 回补会话/父任务版本校验、Worker 版本持久化、后台身份与权限快照、当前联网开关、工具目录一致性及撤销保护。审批来源固定为 v2 或 v3；cloud_bash、host_bash、安装 Skill、MCP 和通用工具分别注册两个版本的执行键，默认切换不会改写待审批行为。v1 不注册执行器。

v2 保留旧 Skill 自动加载策略，未移植 v3 `load_skill`、按需目录或资源副本。旧解析器对 `on_demand` 会按未知模式自动激活，不具备 v3 按需语义；切回 v2 时须预期上下文占用和资源一致性策略不同。来源 blob 清单继续描述原始提取，兼容回补列在 v2 README 中。

历史空版本继续归 v3，不随管理员新会话设置变化；本次不做数据回填或跨版本续跑。版本切换无需重启，不等于旧镜像回滚：回退到只支持 v3 的构建会使已创建的 v2 会话不可执行。恢复 release 设置只影响新会话，已经存在的 v2 会话和审批仍需保留 v2 引擎/执行器，或另行制定迁移方案。

验证范围：共享协议/路由、v2 工具撤销与并发、联网开关、后台权限与任务版本、v2 审批 SSE 恢复；真实 Manager/MySQL + 模型/MCP 替身验证默认切换、双版本动态工具与待审批来源；Chrome 深浅主题、四种宽度及中英文设置交互。测试结果见本轮验证记录，不将替身测试视为真实模型效果验收。
