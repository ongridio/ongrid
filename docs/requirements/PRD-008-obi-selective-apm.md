# PRD-008：OBI 按选择采集

状态：已实现，待部署验收。需求确认：2026-09-14。

在设备详情的插件配置中增加「自动 APM」开关，仅有 off 与 selective 两种行为。默认关闭；开启后发现本机监听进程，只有用户保存的目标才进入 OBI 采集。空目标不启动 OBI 或其 Collector。关闭时停止本功能的发现和采集，保留配置；再次开启恢复保存的目标。现有 SDK、历史查询、日志和持续 Profiling 保持原有行为。

目标以可执行文件的完整路径和监听端口共同选择进程，适用于之后启动的匹配实例；端口用于选择进程，不能解释为仅采集该进程的单个端口。用户为目标设置 service.name、service.namespace，并设置环境与 Trace 采样率。HTTP/gRPC 请求指标独立于 Trace 采样。候选列表仅代表发现监听进程，不保证其协议、TLS 或运行时可被探针识别。点击「添加目标」只修改草稿，保存后才生效。

本期复用每个 Edge 的配置与心跳，不新增集群策略服务、永久服务目录或全量采集模式。Kubernetes 节点使用当前 node DaemonSet 的主机 Agent，按节点配置目标；同一路径与端口可能匹配多个容器中的进程，因此界面明确匹配所有实例。本期不提供按工作负载、namespace 或 Pod label 精确选择，也不自动补充 Kubernetes 服务身份。

验收：默认关闭；空目标只发现；未选进程无遥测；保存失败保留草稿；非法/重复/自身目标被拒绝；缺少二进制/BTF/能力时可见错误；关闭后子进程退出且候选清空；重新开启恢复；零 Trace 采样仍有请求指标；不占用现有 traces 插件端口。

运行与验证见 [ADR-034](../adr/ADR-034-obi-selective-apm.md)。
