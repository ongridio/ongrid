# PRD-008：OBI 按选择采集

状态：已实现，本地部署验证通过。需求确认：2026-09-14；Kubernetes 方案更新：2026-09-16。

服务发现持续开启，不再提供全局开关。普通设备发现监听进程，Kubernetes 使用集群控制器资源清单；只有用户保存的目标才进入 OBI 采集。空目标不启动 OBI 或其 Collector。删除目标停止对应采集，发现继续运行。SDK、历史查询和持续 Profiling 保持原有行为；Kubernetes 容器日志跟随服务选择范围，普通设备可按服务配置文件日志。

普通设备目标以可执行文件的完整路径和监听端口共同选择进程，适用于之后启动的匹配实例；端口用于选择进程，不能解释为仅采集该进程的单个端口。用户为目标设置 service.name、service.namespace，并设置环境。HTTP/gRPC 请求指标独立于 Trace 采样。候选列表仅代表发现监听进程，不保证其协议、TLS 或运行时可被探针识别。从发现结果选择进程只修改草稿，保存后才生效；不提供手动输入路径和端口的入口。

旧 `platform.auto_apm_enabled` 和设备级 `enabled=false` 不再关闭发现。通过现有配置推送及 60 秒轮询同步，离线设备重连后生效。服务页集中展示设备在线、等待上报、发现失败状态、监听候选和已配置目标；设备详情保留跳转入口。

普通设备复用每个 Edge 的目标配置与心跳。Kubernetes 将 Namespace 和工作负载规则保存在集群，复用当前 node DaemonSet 的主机 Agent 执行，并自动补充 Kubernetes 服务身份；不新增独立策略服务、永久服务目录或全量采集模式。

验收：不显示发现开关；新设备及旧禁用配置均自动发现；空目标只发现；未选进程无 OBI 遥测；保存失败保留草稿；非法、重复及系统目标被拒绝；缺少二进制、BTF 或能力时可见错误；清空目标停止 OBI；指标采集独立于 Trace 采样；不占用已有 traces 插件端口。

运行与验证见 [ADR-034](../adr/ADR-034-obi-selective-apm.md)。

实例基础资源（2026-09-20）：实例页上方展示基础资源，下方展示语言运行时监控。基础资源包括操作系统进程 CPU（核）、RSS、虚拟内存、线程数、文件描述符及磁盘读写速率，与语言无关；Python 没有运行时指标时仍可展示基础资源。普通设备按当前选择的可执行文件、端口与 PID 精确关联，不能按进程名合并；Kubernetes 按当前 Pod UID / 容器身份关联容器内进程，RSS 是进程 RSS 合计，不冒充容器工作集。多端口不重复计量、未选择目标不采集，计数器按进程生命周期计算速率再汇总。读取失败留空并报告错误，CPU / I/O 至少两次采集后显示；已退出进程的基础 gauge 不延长到五分钟。环境、实例、设备、集群与版本筛选沿用请求指标身份。基础资源与运行时分别显示空态。

前端交互（2026-09-16）：服务页使用「服务列表 / 服务地图 / 服务发现 / 接入指南」四个固定标签。设备发现表格放在「服务发现」，与请求指标的时间筛选分开；表格分别展示发现状态、发现进程数、已配置目标数和最近上报，未知状态显示占位符，不作为零个目标。配置采集进入独立页面，支持直接访问、刷新及返回对应服务发现范围，默认只读展示已配置目标。点击编辑或底部加号打开单层 Modal。普通设备新增目标从发现进程列表选择，自动带入路径、端口和服务名称，不允许手动填写路径或端口；空发现结果展示等待或空态，不回退到手填。已有目标暂时未发现仍保留身份与日志编辑能力。Kubernetes 继续从命名空间和工作负载清单选择。保存后关闭弹窗并更新页面列表。取消丢弃单条草稿，保存失败保留输入；移除操作在编辑中提供。普通设备和 Kubernetes 使用相同的查看、编辑、添加流程，不再展示全部/已选目标和采集设置标签。采样比例统一为 1，允许自签名证书；Manager 对历史配置也统一下发这两个值。设备离线、状态过期时仍保留已配置目标供编辑，但不显示过期发现结果。SDK 指南保持独立入口。

环境与属性复用（2026-09-16）：设备集群和 Kubernetes 集群均可设置可选默认环境，保存于已有拓扑集群属性。普通设备采集的优先级为目标环境 > 设备默认环境 > 集群默认环境 > 未设置。空值表示继承；修改集群默认值通过下一次配置同步作用于继承目标，不改变显式覆盖或历史数据。Kubernetes 直接继承集群环境，库存同步保留用户环境属性。服务采集使用 `deployment.environment.name` 同时标注指标与链路。同一设备上名称与服务命名空间相同的目标必须使用一致的环境设置，避免 Collector 无法区分同一服务的多个选择规则。

普通设备的环境和服务命名空间支持选择已有配置值，也可输入新值。环境候选由服务端已保存的采集配置、设备默认环境以及集群默认环境去重获得；服务命名空间候选仅取普通设备已保存目标的 `service.namespace`，不混入 Kubernetes Namespace，也不按名称前缀排除普通设备自行配置的同名值。候选不依赖浏览器历史。Kubernetes Namespace 选择器继续使用对应集群的清单。监听候选过滤共用系统组件规则，排除 systemd 及 systemd-*，管理端同样过滤旧版本 Edge 的上报；保存手动目标也执行同一校验。

### Kubernetes 与普通设备分离（2026-09-16）

- 服务发现分为普通设备、Kubernetes 集群；Kubernetes 管理的 Edge 不出现在普通设备采集列表。
- 普通设备保持应用进程的绝对路径 + 监听端口规则，过滤系统和采集器进程。
- Kubernetes 使用既有控制器资源清单，按集群 → Namespace → Deployment / StatefulSet / DaemonSet / Job / CronJob 选择。所选范围始终包含全部容器，不提供容器名称筛选；读取旧配置时清除容器限制。
- “整个 Namespace”是显式持续规则，包含未来工作负载；空规则仅发现，不采集。禁止重叠的 Namespace 和工作负载规则。
- 规则保存在集群，节点执行 OBI 元数据选择器；Pod 重建、扩容、节点加入后无需重新勾选。控制器不运行 OBI。
- Kubernetes 环境直接继承集群默认环境，服务命名空间取实际 Kubernetes Namespace，不允许额外覆盖；Namespace 全选保留各工作负载服务名称。
- 节点状态显示真实心跳与错误，配置保存、运行状态不等同于已收到服务数据。清空规则停止 OBI；集群基础设施清单同步仍由既有控制器维护。
- Helm Chart 统一准备节点 OBI 能力及读取 pods/nodes/replicasets 元数据的权限，不再提供 `node.autoAPM.allowBPF` 开关。用户保存采集目标后启动探针，清空目标停止采集；普通安装和升级命令无需追加参数。
- MySQL 生产发布先执行 `20260916160000_add_k8s_autoapm_config.up.sql`。回滚前清空集群规则，再回滚 Edge 和 Manager；新增列可保留，避免丢失配置。

### Kubernetes 容器日志按服务范围采集（2026-09-20）

- Kubernetes 节点不再默认读取所有容器日志。集群规则为空时停止容器日志文件采集，节点 journald 系统日志持续采集；普通设备日志和 SDK / 网关接入保持原有行为。
- 复用已有 Namespace / 工作负载选择，不新增日志选择表单。整个 Namespace 覆盖未来 Pod；工作负载通过资源清单中的 ownerReferences 解析到当前节点的准确 Pod 名称和 UID，再下发文件路径白名单，不能用工作负载名称前缀猜测。
- 规则保存通知节点重新拉取配置；扩容、滚动更新和 Pod 重建通过现有资源清单与 60 秒配置轮询自动更新。取消选择后停止对应文件读取；未选日志不会先读入再丢弃。
- 仅采集 CRI 标准输出 / 错误日志；沿用 Collector 的 `start_at=end` 和持久化读取位置；恢复读取遵循 Collector 的文件发现及检查点行为。排除节点采集器自身日志，包含自定义 Helm release / namespace。
- 兼容滚动升级：新 Edge 在旧 Manager 无范围配置时不读取容器日志；新 Manager 向旧 Edge 提供不可匹配的旧版单路径，避免退回全量采集。Manager 和节点 Edge 均升级后按选择恢复容器日志。
- 验证默认关闭、Namespace / Deployment / StatefulSet / DaemonSet / Job / CronJob 的全部容器及旧容器限制兼容、同名前缀隔离、动态 Pod、清空；回滚时先回滚 Manager，再显式停用各 Kubernetes 节点的 logs 插件，最后回滚 Edge；直接同时回滚会恢复旧版全量采集默认行为。

### 持续发现与普通设备服务日志（2026-09-20）

- 每个主机目标可填写一个绝对日志路径或 glob；空值不增加该服务的文件日志。路径不允许目录穿越、环境变量替换或控制字符；同一路径不能绑定不同服务身份。
- 路径与目标一同保存、清空及删除，复用 logs 插件和已有后端。日志继承目标服务名、服务命名空间及环境；环境优先级与 OBI 一致。
- 设备已有的日志设置保持原样；服务文件优先于重叠的设备文件规则，避免重复读取。同路径同服务合并为一个 receiver；重叠的服务 glob 按保存顺序匹配。
- 设备日志原本关闭时，仅启用所选服务文件，不恢复 journald 或旧文件规则。去掉全部服务日志后恢复设备原有策略。
- 路径配置保存在 Manager，下发到 logs 的只读 `service_capture`；OBI 快照剔除 `log_path`，兼容旧严格解析器。服务文件日志需要更新 Edge；旧 Edge 不识别新日志范围且不会退回全量文件采集。
- 回滚前清空服务日志路径；停止 OBI 采集通过清空普通设备目标及集群规则完成。升级不修改已有选择，因此已保存目标会继续采集。

### 保留节点基础日志（2026-09-20）

普通设备的 journald 与既有文件日志配置保持原有行为。Kubernetes full-node 同样默认启用宿主机 journald，复用既有 host chroot、journalctl、读取能力及日志后端；不增加权限或挂载。只有 CRI 容器文件 receiver 受服务范围影响：无范围时不创建，选择后添加，清空后撤销，journald 始终保留。控制器不启动节点系统日志采集。节点日志包含 device_id、cluster_id、k8s.node.name；运行状态和错误沿用 logs 插件心跳。

本地回滚使用变更前的 Manager/Edge 镜像；恢复后系统日志会回到旧版缺失状态，容器范围配置保留。对于未提供 journalctl 的主机，采集器按既有普通设备行为上报启动错误，不静默宣称采集成功。

## 设备默认环境（2026-09-20）

默认环境归属设备属性，保存于 `devices.environment`。设备详情「主机信息」与服务发现列表的快捷编辑共用同一接口；未加入集群的设备可以设置自己的环境，留空表示未设置。有集群的设备留空时动态继承集群环境，并展示来源；清空设备覆盖不会复制集群值到设备。Kubernetes 采集仍直接继承集群环境，不受节点设备覆盖影响。

升级时仅对尚未迁移的设备导入首选主机采集器原有默认环境（在线优先，再按最近心跳、ID）；导入后即使清空、重启或更换采集器也不恢复旧值。服务目标的显式环境保留。APM 与服务文件日志使用同一默认值，环境变更通知已连接采集器重新拉取配置，离线设备重连后生效；不重写历史数据。

## OBI 运行时指标（2026-09-20）

发布约束：正式产物仅使用固定版本、通过官方 SHA256 校验的 OBI 原版二进制，不携带 OBI 源码补丁或自维护版本。OrbStack 兼容补丁仅限本地测试，其验证结果不等同于官方原版验收；基础资源采集仍由 Ongrid Edge 实现。

已选目标同时启用 `application` 与 `application_runtime`，沿用现有指标管线和实例筛选。实例页兼容已有 SDK 指标，并展示 OBI 可提供的 Go 内存、分配、GC、调度、Goroutines、运行时 CPU 估算，HotSpot JVM 内存池，以及 Node.js 事件循环指标。Go 运行时 CPU 不等同于进程 CPU，直方图均值标明估算；缺失指标不补零，JVM 内存不标为 RSS。具体支持取决于 OBI 版本、运行时和权限，Python 暂无 OBI 运行时指标，Go / JVM 可能需等 GC 后上报。

普通设备的端口用于选择进程；同一进程同时提供 HTTP 和 gRPC 时，一个目标即可采集两种受支持协议并保留同一服务身份。不需要为同一进程的另一个端口重复配置目标；相同二进制启动的不同进程仍由路径和端口共同区分。

服务发现按同一可执行路径和当前 PID 合并展示监听端口，设备列表数量按进程计数。配置列表与添加弹窗集中展示端口；已有目标匹配到该进程的任意端口后，整个进程不再作为新增候选。同一路径的不同 PID 保持独立，缺少 PID 时不推测合并。保存仍使用路径及一个已发现端口，不持久化易变的 PID；离线或发现结果过期时只展示原保存端口，不改变已有采集配置。
