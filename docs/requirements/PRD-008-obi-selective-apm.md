# PRD-008：OBI 按选择采集

状态：已实现，本地部署验证通过。需求确认：2026-09-14；Kubernetes 方案更新：2026-09-16。

在服务界面提供统一「自动 APM」全局开关及采集管理，仅有 off 与 selective 两种行为。默认关闭；开启后普通设备发现监听进程，Kubernetes 使用集群控制器资源清单，只有用户保存的目标才进入 OBI 采集。空目标不启动 OBI 或其 Collector。关闭时停止本功能的发现和采集，保留配置；集群基础设施清单同步继续由既有控制器维护。再次开启恢复保存的目标。现有 SDK、历史查询、日志和持续 Profiling 保持原有行为。

普通设备目标以可执行文件的完整路径和监听端口共同选择进程，适用于之后启动的匹配实例；端口用于选择进程，不能解释为仅采集该进程的单个端口。用户为目标设置 service.name、service.namespace，并设置环境与 Trace 采样率。HTTP/gRPC 请求指标独立于 Trace 采样。候选列表仅代表发现监听进程，不保证其协议、TLS 或运行时可被探针识别。勾选进程或手动添加只修改草稿，保存后才生效。

全局开关复用 system_settings 的 platform.auto_apm_enabled；所有设备的有效 enabled 以此为准，设备配置接口不能覆盖全局开关。通过现有 60 秒配置轮询同步，离线设备重连后生效。服务页集中展示设备在线/等待上报/发现失败状态、监听候选和已配置目标，并可直接编辑各设备的采集配置；设备详情仅保留跳转入口。

普通设备复用每个 Edge 的目标配置与心跳。Kubernetes 将 Namespace 和工作负载规则保存在集群，复用当前 node DaemonSet 的主机 Agent 执行，并自动补充 Kubernetes 服务身份；不新增独立策略服务、永久服务目录或全量采集模式。

验收：服务页只有一个全局开关；新接入设备自动遵循全局设置；设备级 enabled 不能覆盖全局值；默认关闭；空目标只发现；未选进程无遥测；保存失败保留草稿；非法/重复/自身目标被拒绝；缺少二进制/BTF/能力时可见错误；关闭后子进程退出且候选清空；重新开启恢复；零 Trace 采样仍有请求指标；不占用现有 traces 插件端口。

运行与验证见 [ADR-034](../adr/ADR-034-obi-selective-apm.md)。

前端交互（2026-09-16）：服务页使用「服务列表 / 服务地图 / 服务发现 / 接入指南」四个固定标签。全局开关与设备发现表格放在「服务发现」，与请求指标的时间筛选分开；表格分别展示发现状态、发现进程数、已配置目标数和最近上报，未知状态显示占位符，不作为零个目标。配置复用系统 Modal，进程列表可搜索、勾选并填写服务身份，支持查看已选目标和手动添加；环境、采样、证书设置折叠，底部固定取消与保存操作。关闭全局开关、设备离线、状态过期时仍保留已配置目标供编辑，但不显示过期发现结果。SDK 指南保持独立入口。

环境与属性复用（2026-09-16）：设备集群和 Kubernetes 集群均可设置可选默认环境，保存于已有拓扑集群属性。普通设备采集的优先级为目标环境 > 设备原有环境 > 集群默认环境 > 未设置。空值表示继承；修改集群默认值通过下一次配置同步作用于继承目标，不改变显式覆盖或历史数据。Kubernetes 直接继承集群环境，库存同步保留用户环境属性。服务采集使用 `deployment.environment.name` 同时标注指标与链路。同一设备上名称与服务命名空间相同的目标必须使用一致的环境设置，避免 Collector 无法区分同一服务的多个选择规则。

普通设备的环境和服务命名空间支持选择已有配置值，也可输入新值；候选由服务端已保存的采集配置以及集群默认环境去重获得，不依赖浏览器历史。普通设备的服务命名空间是 `service.namespace`，不作为 Kubernetes Namespace 选择器。监听候选过滤共用系统组件规则，排除 systemd 及 systemd-*，管理端同样过滤旧版本 Edge 的上报；保存手动目标也执行同一校验。

### Kubernetes 与普通设备分离（2026-09-16）

- 服务发现分为普通设备、Kubernetes 集群；Kubernetes 管理的 Edge 不出现在普通设备采集列表。
- 普通设备保持应用进程的绝对路径 + 监听端口规则，过滤系统和采集器进程。
- Kubernetes 使用既有控制器资源清单，按集群 → Namespace → Deployment / StatefulSet / DaemonSet / Job / CronJob 选择。可选容器名称；留空匹配该工作负载全部容器。
- “整个 Namespace”是显式持续规则，包含未来工作负载；空规则仅发现，不采集。禁止重叠的 Namespace 和工作负载规则。
- 规则保存在集群，节点执行 OBI 元数据选择器；Pod 重建、扩容、节点加入后无需重新勾选。控制器不运行 OBI。
- Kubernetes 环境直接继承集群默认环境，服务命名空间取实际 Kubernetes Namespace，不允许额外覆盖；Namespace 全选保留各工作负载服务名称。
- 节点状态显示真实心跳与错误，配置保存、运行状态不等同于已收到服务数据。全局关闭保留规则并停止 OBI；集群基础设施清单同步仍由既有控制器维护。
- 部署仍需显式 `node.autoAPM.allowBPF=true`；仅在此开关开启时授予 OBI 读取 pods/nodes/replicasets 元数据的权限。默认安装权限不变。
- MySQL 生产发布先执行 `20260916160000_add_k8s_autoapm_config.up.sql`。回滚前清空集群规则，再回滚 Edge 和 Manager；新增列可保留，避免丢失配置。
