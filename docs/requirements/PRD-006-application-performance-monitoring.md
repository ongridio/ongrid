# PRD-006: 应用性能监控

## 元信息

- 状态：实现完成，已通过本地定向验证并更新本地测试环境，未部署生产；用户已在 APM 方案讨论中确认架构并授权创建分支实现。
- 日期：2026-09-07
- 作者：Ongrid contributors
- 关联设计：[HLD-002](../design/HLD-002-application-performance-monitoring.md)、[ADR-033](../adr/ADR-033-application-performance-monitoring.md)
- 优先级：P1
- 排期：本功能分支；完成时间以验证结果为准。

## 背景与目标

平台已有 Trace、日志、指标和按需 Profiling，缺少以服务为中心的请求监控。提供「服务异常 → 接口 → Trace → 日志 → 实例诊断」路径；复用官方 OpenTelemetry SDK/Agent，不开发多语言探针。

## 功能需求

1. 在「监控告警」新增「应用性能」。服务按环境、业务命名空间、名称区分。
2. 请求主指标来自应用直接产生的 Metrics，独立于 Trace 采样；支持 HTTP 与 RPC（以 gRPC 做真实接入验收）。服务列表和接口排行以 RPS、错误率、P95 为核心；概览三张趋势图默认使用 P95，延迟支持切换 P50/P99。HTTP/RPC 入口与消息消费分开统计。
3. 服务调用关系展示上下游身份、流量、错误与延迟，缺少配对的数据不伪装成完整拓扑。
4. Trace、日志保留服务和绝对时间筛选；已有 Profile 工具提供按需入口。
5. 提供多语言接入示例、Collector 双目标转发说明和基于真实遥测样本的接入诊断。
6. 请求级告警通过已有规则编辑、预览和执行流程创建，不改变旧 Trace 告警。
7. 运行时数据仅在已上报兼容指标时展示，明确无指标/无 Trace/查询失败/无请求之间的区别。
8. 概览列出所选范围内最近 10 条已采样错误 Trace，可查看详情或启动 AI 只读分析。复用现有会话，按真实 Span 身份串联日志和应用当前性能，展示工具过程及证据缺口；不把模型推断当成确定根因。
9. 服务详情提供「绑定仓库」，按环境、命名空间、服务名保存已接入仓库、相对源码目录及版本 Tag 规则。管理员可保存或解除绑定；AI 读取最新绑定，只在匹配服务的仓库范围内查找，并根据出错实例的版本读取固定 Tag/Commit。版本缺失时不回退主分支。

## 非功能需求与边界

- 查询受登录保护、超时和时间/数量限制；不允许客户端指定后端 URL。
- 复用 Tempo/Prometheus/Loki/Elasticsearch/Pyroscope；无新存储、无数据库迁移。
- 应用 Metrics 与 Trace 派生指标明确分开；后者标明采样覆盖未知，不能用于新的请求级告警。指标接入仍需核验完整性，不能把配置完成当作全量采集成功。
- 旧数据缺少环境或 namespace 时进入“未设置”；不能按同名猜测身份。
- 不包含持续 Profiling、浏览器 RUM、移动端监控、租户化改造及自动根因判定。
- 新增页面复用现有 UI、图表和导航约定，支持中英文及明暗主题。

## API 与数据

新增 `api/manager/apm/v1/apm.proto` 定义服务查询、趋势、接口、依赖、诊断与告警模板。沿用现有 REST Handler 和登录中间件。日志/Profile 的关联扩展是可选参数，不破坏旧调用。

## 依赖、风险与验证

依赖应用已正确埋点及已有遥测后端。不存在应用方接入时，平台只能展示未收到数据。大流量容量与业务开销必须通过目标环境试点确认，不能仅凭单元测试承诺。

- [x] 固定 OTLP 样本验证 server/client 不重复计数、错误率补零、分位数单位。
- [x] 同名服务环境/namespace 隔离，历史缺属性数据正确显示。
- [x] 查询参数、范围、取消、无数据和后端错误被验证。
- [x] 页面导航、筛选、跨页回退、日志 Trace ID 联动通过测试。
- [x] 告警模板与页面使用同一指标定义，旧规则不变。
- [x] Collector/Tempo 配置通过对应固定版本校验。

## 任务拆分

指标契约与样本 → API 与关联查询 → 服务页面与接入说明 → 告警/实例诊断 → 定向回归与配置联调。

## 发布与回滚

先在少量服务启用；新增指标维度保留兼容标签。回滚应用版本和 Collector/Tempo 配置即可恢复旧入口；不回写或删除原始遥测。上线后四周内根据真实数据量、查询耗时和丢弃率复盘。

## 本地验证记录（2026-09-07）

- Go 定向测试带 `-race`，含 Manager 入口编译；前端 36 项定向测试及生产构建通过。
- Tempo 2.10 / Prometheus 2.54：真实 OTLP 固定请求、错误率补零、延迟单位、完整服务身份、服务依赖及诊断验证；Promtool 验证健康/缺数打断持续告警。
- Collector 0.157：配置校验通过；实际文件日志分别写入 Loki 3.4 / ES 8.16，验证同文件多环境隔离与 Trace ID 查询。
- 真实 pprof 经 Collector 和 Profiles Gateway 写入 Pyroscope 1.21，按设备、服务、环境、namespace、实例和绝对时间查询通过。
- 未进行生产部署、容量或业务开销压测；这些结果不能作为生产已接入证明。

## 页面优化与本地更新（2026-09-07）

- 服务列表统一时间选择与环境/命名空间下拉筛选，入口类型收进高级筛选；服务数使用后端筛选后的总数，数据状态不当作健康评分。
- 服务概览集中展示 RED 趋势、按 P95 排列的前五个接口、观测上下游和慢/错误请求入口。单个查询失败保留其他查询成功的结果。
- 详情导航为概览、接口、调用链、依赖、实例；调用链复用现有页面并携带身份和绝对时间。接入管理与创建告警放在辅助操作，实例集中展示样本关联实例、运行时及按需 pprof。
- 使用 Makefile 构建前端镜像 `ongrid-web:dev-apm-overview`，在原 Compose 项目中仅更新 nginx；Manager、Edge 和遥测数据沿用本地已部署版本。前端回滚可将 `ongrid-web:dev-apm-layout` 重新标记为 `ongrid-web:dev` 并用原 Compose 文件重建 nginx。
- 优化后的 APM/API/Trace 8 项定向测试、ESLint 与生产构建通过；已实看服务列表、概览的深浅主题截图和 768px 窄屏布局，并核对英文文案、P95/P99 切换、链路绝对时间、实例空状态、接入诊断和告警模板入口。截图与验收记录保存在本地 `apm-design-review` 目录。

## 原生请求指标修订（2026-09-07）

用户确认调整方案并要求 RPC 支持：默认应用 Metrics、显式 Trace 样本视图；HTTP/RPC 独立选择，标准与旧版指标显式选择，不重复相加。复用主机和 K8s 的现有采集通道。验收必须同时包含真实 HTTP/gRPC 成功、失败、慢请求，以及 Trace 采样降至零时 Metrics 仍记录全部调用。


### 2026-09-07 原生请求指标修订验收

- 应用 Metrics 默认来源，HTTP / RPC 可切换；旧版格式单独选择，Trace 样本视图不静默回退或混算，不能新建请求级告警。
- 官方 Go SDK + HTTP/gRPC 埋点，Trace 采样关闭：各 12 次调用、零导出 Span。实际 Collector 0.157.0 → Prometheus 2.54 查询验证精确计数、25% 错误率、毫秒延迟、接口过滤、当前/旧版 RPC 双发不重复计数。
- 主机 Collector 复用本机 Prometheus exporter + 既有认证隧道，Kubernetes 保留现有 Metrics remote_write；不新增存储或公开写入口。

### 2026-09-08 补齐验收

新增官方 Java/Node/Python 真实 HTTP/gRPC 应用与一条 `make test-apm-acceptance` 验收入口，覆盖采样关闭、指标实例发现、真实请求日志经现有 Collector 写 ES、告警持久化/本地通知/恢复和容量/SDK 开销测试。实例不再只来自 Trace 抽样；通知保留应用身份。Node/Python 官方 gRPC 原生指标支持边界在接入页明确展示。

范围、证据与仍需业务试点确认的项目见 [验收记录](../test/apm-acceptance-20260908.md)，规模与开销见 [压测记录](../ops/loadtest-20260908.md)。历史“未压测”描述仅对应 2026-09-07 当日状态；本轮仍不等同于生产业务验收。

### 2026-09-08 扩展官方语言接入

接入向导和持续 Edge 示例扩展为 Go、Java、Node.js、Python、C# / .NET、PHP、C++、Rust、Ruby。新增示例使用官方 SDK/框架埋点与标准 OTLP；PHP/C++/Rust 通过官方 Metrics API 测量实际请求，Rust 标注 Beta，Ruby 仅提供 Trace 与日志关联。服务列表发现只有 SERVER Trace 的服务。无原生请求指标时，HTTP RED、趋势和接口统计使用 Trace 样本补充，并明确标注样本来源；不推断全量请求统计，不将两种来源相加。新增五语言必须验证开/关采样、真实请求计数、Trace/日志关联、完整服务身份和本地持续运行。证据见同日验收记录与 `examples/apm-languages/README.md`。

### 2026-09-09 错误 Trace 分析验证

- 概览错误列表及 AI 入口已更新本地 Manager/Web；前端 29 项定向测试、ESLint、TypeScript/Vite 构建与 Linux `go test -race ./internal/manager/biz/aiops/tools -run TestQueryTraceQL` 通过。
- 浏览器点击真实 Java 错误 Trace `cec04114ffe111d760b88c9586ddd724`，默认助理读取完整单 Span，关联到 Elasticsearch 中相同 Trace/Span ID 的请求日志，查询到实例 `ubuntu-java-2` 的 HTTP 状态码速率、P95、JVM CPU 和进程 RSS，最终生成分析报告。日志首次参数校验失败，模型修正流选择器后成功；工具过程可在会话中展开核对。
- 本轮验证了数据关联与分析流程，不代表模型结论全部正确。模型未进一步查询 RPC/其他 JVM 指标，且对单 Span、短窗口 CPU/RSS 的排除性措辞偏强；这些证据不足以断言无下游故障、无 OOM 或无泄漏，根因仍需人工审阅与补证。未部署生产。
### 2026-09-11 查询减负、错误聚合与版本对比

用户确认本轮实现三项增量：非实例页面只发现实例、不查询运行时曲线；错误按接口、异常类型、状态和堆栈聚合并保留代表链路与 AI 分析；同一时间及设备/集群范围内比较两个版本的请求数、RPS、错误率、P95/P99，HTTP/RPC 分开展示。

错误聚合每种协议最多读取 50 条已采样错误链路，手动刷新；次数与首次/最近时间仅对应本次样本。版本比较覆盖两个版本的全部已观测实例，来源或采样口径不同时不计算差值，缺失数据不补零。验收及本地回滚见 [验证记录](../test/apm-groups-comparison-20260911.md)。
