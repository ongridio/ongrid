# PRD-002：Edge 上联网络设备发现与统一身份

## 元信息

- 状态：开发中
- 作者：Ongrid
- 日期：2026-07-29
- 关联 issue：#199
- 关联 ADR：ADR-030-network-device-identity
- 关联 HLD：不适用（复用现有 Edge tunnel、Device 和 Topology）

## 背景

当前 `devices` 主要表示安装了 Edge 的主机。运维人员还需要在同一设备列表和拓扑中看到交换机、路由器、防火墙等上联网络设备，并能够在多个 Edge、LLDP 和 SNMP 结果之间保持同一个设备身份。

## 目标

- 开启网络发现后，Edge 能上报默认网关、邻居和 LLDP 发现结果；这些结果先进入候选区，不直接创建正式设备。
- 管理员可在设备页的“网络发现”标签配置 SNMP v2c/v3；只有只读 SNMP 身份校验成功后，候选才进入全部设备和正式拓扑。
- 同一网络设备经多个来源发现后只保留一个 `devices.id`。
- 管理 IP 或 hostname 变化不会制造重复设备。
- 自动发现只追加 `network` 角色，不覆盖人工角色或人工取消记录。
- 设备详情可查看发现来源、身份标识、置信度、接口和链路。

## 功能需求

### 第一阶段

- 平台全局配置提供网络发现开关，默认开启；关闭后 Manager 忽略新的候选上报。Edge 环境文件仍可对单台主机显式关闭本地采集。
- 默认发现默认网关、ARP/Neighbor、LLDP 邻居；不做 CIDR 全网扫描。
- SNMP 使用管理员配置的只读凭据，仅查询 sysName、sysDescr 和 sysObjectID；一期凭据仅在单次扫描内存中使用，不落库、不回显，接口和 LLDP MIB enrichment 后续补齐。
- SNMP 校验同时读取 IF-MIB 接口状态与 IPv4 地址归属；SNMPv3 支持 SHA-1/SHA-2 认证及 AES-128/192/256 隐私协议，配置项使用受控选项而非任意字符串。
- 未通过 SNMP 校验的候选不能调用 promote 接口绕过准入。
- 发现结果幂等写入 `devices`、`device_network`、`device_identifiers`、`network_interfaces`、`network_links`。
- 自动发现设备与发现 Edge 建立 `edge_devices(type=discovered)` 关系。
- 自动网络角色支持人工 override；人工移除后不自动加回。

### 身份归并

身份优先级和冲突规则由 ADR-030 定义。只有管理 IP 或 sysName 不得永久合并。

### 暂不包含

- CIDR 主动扫描。
- 自动写入网络设备配置。
- 将堆叠成员拆成多个顶层设备。

## 非功能需求

- SNMP 凭据不进入日志、API 响应或发现结果快照；当前一期不持久化凭据，后续如需复用应接入 Secret vault 加密存储。
- 单次发现批次有界：设备、接口、链路和标识数量均有上限，避免 Edge 将异常响应放大到 Manager。
- 发现上报失败可重试且幂等，不阻塞 Edge 心跳和主机指标采集。
- 所有写入使用短事务；不在事务内调用网络设备。

## 数据库变更

新增 `device_network`、`device_identifiers`、`network_interfaces`、`network_links`。详情见 ADR-030 与实现中的 GORM 模型。现有 `devices` 和 `edge_devices` 保持兼容。

## 验收标准

- [ ] 全局开关关闭时 Manager 不创建或更新网络发现候选。
- [ ] 开关开启后能上报默认网关和 LLDP 邻居。
- [ ] LLDP 与 SNMP 命中强身份时归并为同一个 `devices.id`。
- [ ] 只有 IP/sysName 相同不会自动永久合并。
- [ ] 自动发现设备获得 `network` 角色，人工角色不被覆盖。
- [ ] 设备详情能列出来源、标识、置信度、接口和链路。
- [ ] SNMP 接口快照能展示 ifIndex 对应的 IPv4 地址。
- [x] SNMP 凭据不会出现在日志和 API 响应中。
- [x] 候选设备单独展示在设备页“网络发现”标签，不污染“全部设备”。
- [x] 只有 SNMP 身份校验成功的候选才会创建正式 Device。
- [ ] 重复批次不会产生重复设备、标识、接口或链路。

## 2026-10-27 增补：统一 SNMP 配置入口

管理员在网络设备列表、设备详情和发现候选中使用同一配置弹窗。界面统一称为“扫描源”，默认选择发现该设备的 Host，可选择其他在线 Host；配置持久化 Host ID，执行时解析当前有效 Edge，采集数据仍归目标网络设备。

配置包含管理 IP、端口、扫描源、Secrets 凭证引用、采集开关与间隔。弹窗支持创建 SNMP v2c/v3 凭证，沿用现有协议能力；凭证加密存入 Secrets，关闭配置弹窗不删除明确创建的共享凭证。旧的一次性明文凭证 API 保持兼容。

“测试连接”验证未保存配置，不修改候选、正式设备或采集状态；启用配置与候选加入设备时，服务端再次执行验证。编辑参数后旧测试结果失效。停用保留配置，可在扫描源离线时保存停用状态。扫描源连接失败标记采集失败/目标状态未知，不断言目标设备不可达。

验收覆盖：列表/详情/候选入口、v2c/v3、凭证引用不泄露、失败保留草稿、停用、扫描源 Edge 更换、服务端校验、明暗主题及移动端。范围不包含 Trap、厂商 MIB 模板或完整时序采集。

持久化增加 `device_network.poll_scanner_host_device_id`，沿用项目 AutoMigrate；旧记录从经过验证的发现来源关联初始化扫描源，缺失关联时要求重新选择，不猜测 ID。新旧版本不得同时修改同一 SNMP 配置；回滚前停用使用自定义扫描源的轮询，保留新增列和 Secrets。

本次本地验证：设备业务/HTTP/存储包 `go test -race` 通过；相关前端单元测试 25 条通过；基于 Mock API 的 Chrome 浏览器流程 8 条通过，覆盖三个入口及移动端的明暗主题，截图已实看；前端生产构建通过。另执行 Manager 全包编译检查，macOS 下仅 `biz/aiops/tools` 因依赖 Linux 专用 `edgeagent/cmdpolicy` 无法完成。浏览器验证不代表真实 SNMP 网络链路验收，交换机 v2c/v3 凭证、扫描源隧道及周期采集仍需部署后联调。

### 手动添加入口（2026-10-28 更正）

本轮的主要入口应为“网络设备 → 添加 SNMP 设备”，右上角与空状态均提供操作。用户直接填写管理 IP、端口、扫描源和凭证，不要求已有网络发现候选。测试通过后由服务端再次验证，并在事务中创建正式设备、采集配置和接口快照；不伪造网络发现记录或物理拓扑连接。已有身份返回冲突，不覆盖原设备配置。新设备无候选记录时同样支持详情和周期采集。“网络发现 → 配置 SNMP”是已有辅助入口，不能替代手动添加主流程。

### 2026-10-31：扫描源采集关系

- 手动添加及候选纳管都自动创建设备拓扑节点；以扫描源 Host 为源、网络设备为目标建立 `collects_from`（采集自）关系。
- 关系绑定 Host ID，不绑定运行时 Edge ID，也不填写网卡端点。Edge 重装只影响执行连接，不影响该关系。
- 采集关系不表示物理直连，不参与故障传播；LLDP 及端口级邻接不是本次接入的前置条件。
- 停用轮询保留配置关联并标记停用；切换扫描源替换本模块拥有的旧采集关系。
- 后台分页核对既有网络设备（含停用设备），补齐节点与关系，并移除来源明确为 `network_discovery` 的旧自动 `connected_to`。手工或其他来源的连接不变。
- 验收：新建立即有关联；重装 Edge 关联稳定；改源不留旧自动关联；停用可识别；既有设备自动补齐；物理连接不被误删。

### 2026-10-31：Agent 的网络设备状态语义

- `Device.Online` 继续只表示 Host/Edge 心跳；SNMP 工具不返回该字段。通用设备工具仅对 Host 返回 `online`，SNMP 返回 `device_type=snmp`、`reachability_status` 及采集证据。
- 通用 `status=online` 对 SNMP 匹配近期可达；`offline` 只匹配明确不可达；采集异常、扫描源离线/不可用、停用和过期属于 `unknown`，不得推断目标离线。
- 工具返回扫描源 Host ID/名称/在线状态、定时采集开关、最近采集和成功时间、最近错误。新鲜度窗口为两倍轮询间隔加 30 秒调度余量（未配置间隔按 300 秒）。
- 两类工具均分页取数后按对应语义筛选，避免先按 Host 心跳或先截断导致漏掉网络设备。普通 Host 即使带 network 角色，仍使用 Host 状态。
